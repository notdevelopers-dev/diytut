# Фронтенд

React + TypeScript 7 + Vite. Бекенд піднімається за інструкцією в [головному README](../README.md#локальна-розробка).

## Запуск

Спершу підніміть бекенд. Потім з кореня репозиторію:

```bash
cd frontend
npm ci
npm run dev
```

Сайт відкриється на <http://localhost:5173>. Зміни в коді підхоплюються одразу.

`npm ci` ставить рівно ті версії, що записані в `package-lock.json`. Використовуйте його для звичайного встановлення, а `npm install <пакет>` — лише коли додаєте нову залежність. Інші менеджери пакетів (yarn, pnpm) не використовуємо, щоб не було кількох lock-файлів.

## Запуск у контейнері (без Node на машині)

Vite можна запустити в Docker разом з рештою стеку. Сервіс `web` вимкнений за замовчуванням і вмикається профілем (з кореня репозиторію):

```bash
docker compose --profile web up -d
```

Щоб не писати `--profile` щоразу, додайте в локальний `.env` рядок `COMPOSE_PROFILES=web`.

Сайт буде на тій самій адресі <http://localhost:5173>. При кожному старті контейнер синхронізує залежності з `package-lock.json`, тож після `git pull` з новими пакетами досить `docker compose restart web`. Команди npm виконуються всередині контейнера:

```bash
docker compose exec web npm install <пакет>
docker compose exec web npm run lint
docker compose exec web npm run format
```

`node_modules` у контейнері живе в окремому томі й не перетинається з `frontend/node_modules` на вашій машині: частина пакетів (наприклад, Oxlint) містить скомпільовані файли під конкретну ОС, тож одна тека для Windows і Linux не годиться. Не запускайте одночасно `npm run dev` на машині й сервіс `web` — обидва займають порт 5173.

## Скрипти

| Команда                | Що робить                                         |
|------------------------|---------------------------------------------------|
| `npm run dev`          | dev-сервер з автооновленням                       |
| `npm run build`        | перевірка типів і продакшн-збирання в `dist/`     |
| `npm run typecheck`    | лише перевірка типів                              |
| `npm run lint`         | Oxlint, разом із правилами, що враховують типи    |
| `npm run format`       | відформатувати код                                |
| `npm run format:check` | перевірити форматування, нічого не змінюючи       |
| `npm run preview`      | переглянути зібраний `dist/` локально             |

Перед комітом мають проходити `format:check`, `lint` і `build`.

## Звернення до API

- **У коді — лише відносні шляхи:** `fetch('/api/volunteers')`, без домену й порту. У розробці Vite пересилає `/api` на бекенд, у продакшні це робить nginx, тож код однаковий для обох середовищ і CORS не потрібен.
- Проксі за замовчуванням іде на `http://127.0.0.1:8000`. Якщо бекенд у вас на іншій адресі, задайте змінну `API_PROXY_TARGET` перед `npm run dev`.
- Автодокументація API: <http://localhost:5173/api/docs>.

## Змінні оточення

Змінні з префіксом `VITE_` потрапляють у код, який завантажує браузер. Тому не ставте секрети в них: усе, що бачить фронтенд, бачить і будь-який користувач.

## Редактор (VS Code)

Встановіть розширення:

- **TypeScript 7** (видавець Microsoft) — мовний сервер TypeScript 7. Перемикається командами «Enable / Disable TypeScript 7 Language Server» у палітрі команд;
- **Oxc** — підсвічування помилок Oxlint;
- **Prettier** — форматування.

## Версії TypeScript і лінтера

`typescript` і `oxlint-tsgolint` оновлюються лише разом: номер tsgolint відповідає версії TypeScript (наприклад, `7.0.2004` — збірка під TypeScript `7.0.2`). Dependabot приносить їх одним PR; перевіряйте, що версії відповідають одна одній.
